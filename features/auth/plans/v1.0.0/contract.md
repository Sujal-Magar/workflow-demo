# API Contract: Authentication and Identity (`auth`) v1.0.0

Status: DRAFT (revision 3) for Plan Review, then frozen at the Developer Approval Gate. Revision 3 rewords the default `INTERNAL_ERROR` and `VALIDATION_ERROR` informational messages (section 5) and states that the Bearer header is sent only on Bearer operations (sections 1, 4.4, 7); no operation, shape, status code or field message changed. Revision 2 added: the not-a-string rule for every string field (section 3), an informational `message` text per error code (section 5), and advisory 10-A5 (email trimming); no operation, shape, status code or field message changed. Revision 1 changed only the handling of request bodies that are present but not JSON objects (sections 1 and 5, resolution 9-R3), and clarifies the CORS methods wording (section 6) and the refresh cookie-clearing resolution (9-R4). No operation, shape, status or message changed.
Source of truth for the Frontend/Backend interface. Companion to `plan.md`.
Derived from: `features/auth/fds.md` v1.0.0 (sections 3, 4, 5, 6), `features/auth/behavior.md`, and the two plan fragments (superseded by the plan and this file).

This document is plain-language and technology-agnostic. It contains no framework, schema-library or SDL syntax. Translating it into the project's typed contract package (`packages/contracts`) is Backend Build's job.

Where the FDS already defines a value (message text, status code, error code), this contract copies it verbatim and cites the FDS section. Where the two fragments implied different shapes, or the FDS is silent on a detail the interface needs, the decision is recorded in section 9 (Resolutions) or section 10 (Advisory Items). There are **no Blocking items**.

## 1. Conventions

| Topic                  | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| :--------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Base path              | Every operation path below is absolute from the API origin and includes the version prefix, e.g. `/api/v1/auth/login`. The API origin itself (e.g. `http://localhost:4000`) is configuration, not part of the contract.                                                                                                                                                                                                                                                                                                                                                                       |
| Body format            | Request and response bodies are JSON (`Content-Type: application/json`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Character handling     | Strings are UTF-8. Field names are case-sensitive and camelCase.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Unknown request fields | Ignored (never persisted, never echoed).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Timestamps             | Not exposed by any auth operation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Auth schemes           | **Public**: none. **Cookie**: the `refresh_token` cookie. **Bearer**: header `Authorization: Bearer <accessToken>`. Each operation uses exactly one scheme (section 4). Only Bearer operations use the `Authorization` header (in this feature `getCurrentUser`; every protected endpoint of other features); the seven other operations (`register`, `login`, `googleOAuthLogin`, `refreshSession`, `requestPasswordReset`, `resetPassword`, `logout`) are Public or Cookie, neither require nor read `Authorization`, and clients do not send it on them. `logout` is cookie-authenticated. |
| Credentials            | The client sends every auth request with cookies included (cross-origin credentialed requests).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Body-less operations   | `refreshSession` and `logout` take no request body. The server MUST accept a request with no body, and also a body of `{}`, and ignore it. A client is not required to send `Content-Type` for them.                                                                                                                                                                                                                                                                                                                                                                                          |
| Absent required body   | For operations that require a body, a **missing or empty body** (no content) is treated as an empty object, so every required field reports its own "is required" message (section 3).                                                                                                                                                                                                                                                                                                                                                                                                        |
| Non-object body        | A body that is **present but valid JSON of a non-object type** (an array, a string, a number, a boolean or `null`) is rejected with `400 VALIDATION_ERROR` and an empty `fieldErrors` map, exactly like a body that is not parseable JSON (section 5, 9-R3). It is not treated as an empty object.                                                                                                                                                                                                                                                                                            |

## 2. Shared Shapes

### 2.1 `User`

Exactly three fields, nothing else. Never `passwordHash`, `googleId`, `provider`, timestamps or token data.

| Field   | Type          | Notes                                        |
| :------ | :------------ | :------------------------------------------- |
| `id`    | string (UUID) | Stable user identifier.                      |
| `name`  | string        | Display name, as stored (trimmed, see 9-R9). |
| `email` | string        | Lowercase (normalized).                      |

### 2.2 `SessionBody` (returned by `register`, `login`, `googleOAuthLogin`, `refreshSession`)

| Field         | Type    | Notes                                                                                                                                |
| :------------ | :------ | :----------------------------------------------------------------------------------------------------------------------------------- |
| `user`        | `User`  | The authenticated user.                                                                                                              |
| `accessToken` | string  | Signed access token. Opaque to the frontend. Sent back as a Bearer token.                                                            |
| `expiresIn`   | integer | Access-token lifetime in **seconds**. The value is `900` in v1. The frontend MUST use the returned value and MUST NOT hard-code 900. |

The refresh token is never present in any response body. It travels only in the `refresh_token` cookie.

### 2.3 `SuccessBody` (returned by `logout`, `resetPassword`)

| Field     | Type    | Value          |
| :-------- | :------ | :------------- |
| `success` | boolean | Always `true`. |

### 2.4 `SuccessMessageBody` (returned by `requestPasswordReset`)

| Field     | Type    | Value                                                                             |
| :-------- | :------ | :-------------------------------------------------------------------------------- |
| `success` | boolean | Always `true`.                                                                    |
| `message` | string  | Always exactly `If an account exists for that email, a reset link has been sent.` |

The frontend renders its own fixed copy for this state and does not depend on `message`.

### 2.5 `ErrorBody` (every non-2xx response)

| Field         | Type                        | Present                             | Notes                                                                                                                                                                                         |
| :------------ | :-------------------------- | :---------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `code`        | string                      | Always                              | One of the codes in section 5.                                                                                                                                                                |
| `message`     | string                      | Always                              | Human-readable, actionable, never contains enumeration-sensitive facts, stack traces or secrets. Clients branch on `code`, never on `message`.                                                |
| `fieldErrors` | map of field name to string | Only when `code = VALIDATION_ERROR` | One entry per failing field, holding the **first failing rule's** message for that field. Keys are the request field names exactly (`name`, `email`, `password`, `confirmPassword`, `token`). |

## 3. Field Rules and Messages (FDS section 5)

Messages are fixed strings, identical wherever the rule applies. The frontend shows them inline; the backend returns them in `fieldErrors`. Rules are evaluated in the order listed for each field; only the first failure is reported.

| Field             | Order | Rule violated                                                                                         | Message                                                                                                         |
| :---------------- | :---- | :---------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------- |
| `name`            | 1     | empty (after trim)                                                                                    | `Name is required.`                                                                                             |
| `name`            | 2     | fewer than 2 characters (after trim)                                                                  | `Name must be at least 2 characters.`                                                                           |
| `email`           | 1     | empty (after trim)                                                                                    | `Email is required.`                                                                                            |
| `email`           | 2     | not a syntactically valid `name@domain.tld`                                                           | `Enter a valid email address.`                                                                                  |
| `password`        | 1     | empty                                                                                                 | `Password is required.`                                                                                         |
| `password`        | 2     | fewer than 8 characters                                                                               | `Password must be at least 8 characters.`                                                                       |
| `password`        | 3     | no digit (`0-9`)                                                                                      | `Password must include a number.`                                                                               |
| `password`        | 4     | no special character (any character that is not an ASCII letter or digit; space and underscore count) | `Password must include a special character.`                                                                    |
| `confirmPassword` | 1     | empty                                                                                                 | `Please confirm your password.`                                                                                 |
| `confirmPassword` | 2     | not exactly equal to `password`                                                                       | `Passwords do not match.`                                                                                       |
| `token`           | 1     | missing, not a string, or empty                                                                       | Not user-visible; text is implementation-defined (see 10-A2). The key `token` MUST be present in `fieldErrors`. |

Rule scoping per operation:

- **Password strength (orders 2 to 4)** applies to `register` and `resetPassword` only. `login` applies only "empty" (order 1). Existing credentials are never held to the strength rule.
- **`confirmPassword` mismatch** is reported under the `confirmPassword` key, even if `password` itself also failed a rule. The mismatch check runs whenever `confirmPassword` is non-empty.
- **Non-string values**: for every string field (`name`, `email`, `password`, `confirmPassword`, `token`), a value that is missing, `null` or not a string (number, boolean, array, object) is treated as absent. For `name`, `email`, `password` and `confirmPassword` it is reported with that field's order-1 "is required" message from the table above (`Please confirm your password.` for `confirmPassword`); for `token` the key `token` is present in `fieldErrors` (10-A2). The Google ID token is carried in the request field `token`.
- **Trimming and normalization**: `email` is trimmed, then lowercased, before validation, lookup and storage (10-A5). `name` is trimmed before validation and storage (10-A1). `password`, `confirmPassword`, and both `token` fields are never trimmed or altered.

## 4. Operations

Every operation may also return `400 VALIDATION_ERROR` where it takes a body, and any operation may return an unexpected-failure response (section 5, `INTERNAL_ERROR`). Those are not repeated per operation unless something specific applies.

### 4.1 `register`

| Item            | Definition                                                                                                                                                                                                                                                               |
| :-------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Method and path | `POST /api/v1/auth/signup`                                                                                                                                                                                                                                               |
| Auth            | Public                                                                                                                                                                                                                                                                   |
| Request body    | `name`, `email`, `password`, `confirmPassword` (all strings, all required)                                                                                                                                                                                               |
| Success         | `201 Created`, body `SessionBody`, plus `Set-Cookie: refresh_token` (section 6)                                                                                                                                                                                          |
| Errors          | `400 VALIDATION_ERROR` (fields: `name`, `email`, `password`, `confirmPassword`); `409 EMAIL_ALREADY_EXISTS`                                                                                                                                                              |
| Behavior        | Creates an account with provider `email`. `409` applies when any account, including a Google-created one, already has that email (case-insensitive, after normalization). No profile record is created (the `profile` feature owns that). No cookie is set on any error. |

### 4.2 `login`

| Item            | Definition                                                                                                                                                                                                                             |
| :-------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Method and path | `POST /api/v1/auth/login`                                                                                                                                                                                                              |
| Auth            | Public                                                                                                                                                                                                                                 |
| Request body    | `email`, `password` (both strings, both required)                                                                                                                                                                                      |
| Success         | `200 OK`, body `SessionBody`, plus `Set-Cookie: refresh_token`                                                                                                                                                                         |
| Errors          | `400 VALIDATION_ERROR` (fields: `email` for empty or malformed, `password` for empty); `401 INVALID_CREDENTIALS`                                                                                                                       |
| Behavior        | `401 INVALID_CREDENTIALS` is the single failure for an unknown email, a wrong password, and an account with no password. The status, code, message and body are byte-identical across the three causes. No cookie is set on any error. |

### 4.3 `googleOAuthLogin`

| Item            | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| :-------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Method and path | `POST /api/v1/auth/google`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Auth            | Public                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Request body    | `token` (string, required): the Google ID token, sent as returned by Google                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Success         | `200 OK`, body `SessionBody`, plus `Set-Cookie: refresh_token`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Errors          | `400 VALIDATION_ERROR` (field: `token`); `401 INVALID_GOOGLE_TOKEN`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Behavior        | Verifies the token (signature, expiry, audience). `401 INVALID_GOOGLE_TOKEN` also applies when the token's email is not verified, when Google sign-in is not configured on the server, and when the account found by email already has a **different** Google identity (that account is left unchanged). Account resolution order (FDS REQ-AUTH-03): (1) account with this Google identity signs in; (2) else account with this email is linked (provider and password kept) and signs in; (3) else a new account is created (provider `google`, no password; name resolved by the FDS name-resolution rule). New, existing and newly linked accounts return the identical response shape. No cookie is set on any error. |

### 4.4 `refreshSession`

| Item            | Definition                                                                                                                                                                                                                                                                                                                                                    |
| :-------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Method and path | `POST /api/v1/auth/refresh`                                                                                                                                                                                                                                                                                                                                   |
| Auth            | Cookie (`refresh_token`); no `Authorization` header is needed or read                                                                                                                                                                                                                                                                                         |
| Request body    | None                                                                                                                                                                                                                                                                                                                                                          |
| Success         | `200 OK`, body `SessionBody`, plus a **rotated** `Set-Cookie: refresh_token` (new value)                                                                                                                                                                                                                                                                      |
| Errors          | `401 UNAUTHENTICATED`                                                                                                                                                                                                                                                                                                                                         |
| Behavior        | Revokes the presented refresh token and issues a new one. `401 UNAUTHENTICATED` when the cookie is absent, unknown, revoked or expired, or when the token's user no longer exists. **Every** `401` from this operation also carries a `Set-Cookie` that clears `refresh_token`. Safe to call from a fresh page load. A revoked token can never succeed again. |

### 4.5 `getCurrentUser`

| Item            | Definition                                                                                                                                                                                                                                                                                |
| :-------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Method and path | `GET /api/v1/auth/me`                                                                                                                                                                                                                                                                     |
| Auth            | Bearer                                                                                                                                                                                                                                                                                    |
| Request body    | None                                                                                                                                                                                                                                                                                      |
| Success         | `200 OK`, body `{ user: User }`                                                                                                                                                                                                                                                           |
| Errors          | `401 UNAUTHENTICATED`                                                                                                                                                                                                                                                                     |
| Behavior        | `401` for a missing, malformed, wrong-scheme, tampered or expired access token, or when the token's user no longer exists. The v1 frontend derives the user from session responses and does not call this operation; it is still part of the contract and must be implemented and tested. |

### 4.6 `logout`

| Item            | Definition                                                                                                                                                                                                       |
| :-------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Method and path | `POST /api/v1/auth/logout`                                                                                                                                                                                       |
| Auth            | Cookie (optional in effect)                                                                                                                                                                                      |
| Request body    | None                                                                                                                                                                                                             |
| Success         | `200 OK`, body `SuccessBody`, plus a `Set-Cookie` that clears `refresh_token`                                                                                                                                    |
| Errors          | None from credentials                                                                                                                                                                                            |
| Behavior        | Revokes the presented refresh token if it exists and is active. Always returns `200` and clears the cookie, including when no cookie, an unknown cookie, an expired cookie or an already-revoked cookie is sent. |

### 4.7 `requestPasswordReset`

| Item            | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| :-------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Method and path | `POST /api/v1/auth/forgot-password`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Auth            | Public                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Request body    | `email` (string, required)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Success         | `200 OK`, body `SuccessMessageBody`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Errors          | `400 VALIDATION_ERROR` (field: `email`, empty or malformed)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Behavior        | For any well-formed email the response is identical whether the email is registered, unregistered or belongs to a Google-only account. If the account exists, every earlier unused reset token of that user is invalidated first (at most one valid link per user), then a new token valid for 30 minutes is created and the link `<FRONTEND_ORIGIN>/reset-password?token=<rawToken>` is handed to the mailer port (development delivery: printed to the server console; no HTTP effect). A mailer failure does not change the response. No cookie is set. |

### 4.8 `resetPassword`

| Item            | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| :-------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Method and path | `POST /api/v1/auth/reset-password`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Auth            | Public                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Request body    | `token` (string, required, the raw value from the reset link), `password`, `confirmPassword`                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Success         | `200 OK`, body `SuccessBody`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Errors          | `400 VALIDATION_ERROR` (fields: `token`, `password`, `confirmPassword`); `400 INVALID_RESET_TOKEN`                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Behavior        | `400 INVALID_RESET_TOKEN` for a token that is unknown, expired (30 minutes after issue), already used, or superseded by a newer request. Validation runs first: a request with a weak password or mismatched confirmation returns `VALIDATION_ERROR` and the token stays usable. On success, atomically: the password is set (or replaced; a Google-only account gains its first password and keeps provider `google`), the token is marked used, and **all** of the user's refresh tokens are revoked. No session is issued and no cookie is set or cleared. |

## 5. Error Catalogue

| Status | `code`                 | Meaning                                                                                                                                                                                                                                                                         | Operations                                                                        |
| :----- | :--------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------------- |
| 400    | `VALIDATION_ERROR`     | Request fails validation; includes `fieldErrors`. Also returned for a request body that is not parseable JSON, and for a body that is present but valid JSON of a non-object type (array, string, number, boolean, `null`); in both cases `fieldErrors` is an empty map (9-R3). | `register`, `login`, `googleOAuthLogin`, `requestPasswordReset`, `resetPassword`  |
| 400    | `INVALID_RESET_TOKEN`  | Reset token unknown, expired, used or superseded.                                                                                                                                                                                                                               | `resetPassword`                                                                   |
| 401    | `INVALID_CREDENTIALS`  | Login failed (one cause-independent failure).                                                                                                                                                                                                                                   | `login`                                                                           |
| 401    | `INVALID_GOOGLE_TOKEN` | Google token failed verification, unverified email, not configured, or conflicting Google identity.                                                                                                                                                                             | `googleOAuthLogin`                                                                |
| 401    | `UNAUTHENTICATED`      | Missing, invalid, expired or revoked credential.                                                                                                                                                                                                                                | `refreshSession`, `getCurrentUser`, and every protected endpoint of every feature |
| 409    | `EMAIL_ALREADY_EXISTS` | Registration with an email that already has an account.                                                                                                                                                                                                                         | `register`                                                                        |
| 500    | `INTERNAL_ERROR`       | Unexpected server failure. Generic message, no internals. Non-normative (10-A3).                                                                                                                                                                                                | any                                                                               |

Informational `message` text per code. The body always carries a `message`, but it is informational only: clients never display it, branch on it or assert on it (they use `code`, and their own copy). Each code has one fixed generic string, so bodies for the same code are always identical (which the byte-identical `INVALID_CREDENTIALS` rule in 4.2 relies on); the exact wording is a default, not a contract guarantee, except that it is constant per code and leaks nothing.

| `code`                 | Default `message`                            |
| :--------------------- | :------------------------------------------- |
| `VALIDATION_ERROR`     | `The request has missing or invalid fields.` |
| `INVALID_RESET_TOKEN`  | `This reset link is invalid or has expired.` |
| `INVALID_CREDENTIALS`  | `Invalid email or password`                  |
| `INVALID_GOOGLE_TOKEN` | `Google sign-in failed.`                     |
| `UNAUTHENTICATED`      | `Authentication required.`                   |
| `EMAIL_ALREADY_EXISTS` | `An account with this email already exists.` |
| `INTERNAL_ERROR`       | `The server could not complete the request.` |

Frontend handling rule: any status or code not listed for an operation is treated as a generic failure using the FDS section 5 "Generic Failure Feedback" copy. Clients never branch on `INTERNAL_ERROR`.

## 6. Refresh Cookie and Transport

| Attribute  | Value                                                                                                                                                              |
| :--------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Name       | `refresh_token`                                                                                                                                                    |
| Value      | Opaque 256-bit random value, base64url. Never appears in a body or a log.                                                                                          |
| `HttpOnly` | Yes                                                                                                                                                                |
| `SameSite` | `Lax`                                                                                                                                                              |
| `Path`     | `/api/v1/auth`                                                                                                                                                     |
| `Max-Age`  | `604800` (7 days)                                                                                                                                                  |
| `Secure`   | Set when the server runs in production mode (`NODE_ENV=production`), otherwise not set                                                                             |
| Clearing   | A `Set-Cookie` for the same name with identical `Path`, `HttpOnly` and `SameSite`, `Max-Age=0` (and an expiry in the past). A differing `Path` would not clear it. |

Which responses set, rotate or clear the cookie:

| Response                                            | Cookie effect                        |
| :-------------------------------------------------- | :----------------------------------- |
| `register` 201, `login` 200, `googleOAuthLogin` 200 | Set (new token)                      |
| `refreshSession` 200                                | Rotated (new value, old one revoked) |
| `refreshSession` 401                                | Cleared                              |
| `logout` 200                                        | Cleared                              |
| All other responses                                 | Untouched                            |

Access token: signed, HS256, lifetime 15 minutes (`expiresIn = 900`), carries the user id as its subject and no personal data. Held in frontend memory only, never in `localStorage`, `sessionStorage` or a cookie.

Cross-origin rules (the frontend and API run on different origins, e.g. `http://localhost:3000` and `http://localhost:4000`):

- `Access-Control-Allow-Origin` equals the configured frontend origin exactly (never `*`).
- `Access-Control-Allow-Credentials: true`.
- `Access-Control-Allow-Headers` includes `Content-Type` and `Authorization`.
- `Access-Control-Allow-Methods` includes `GET`, `POST`, `OPTIONS`, the methods this feature needs; it may list further methods (for example `PATCH` and `DELETE`, which other features' endpoints use) and MUST NOT be narrowed below these.
- `Vary: Origin`. A preflight `OPTIONS` request returns `204`.

## 7. Contract for Other Features (Protected Endpoints)

Every endpoint of every other feature requires the Bearer scheme, enforced by the shared `requireAuth` middleware (FDS REQ-AUTH-08):

- Missing header, scheme other than `Bearer`, empty token, bad signature, malformed token, or expired token: `401`, `ErrorBody` with `code = UNAUTHENTICATED`.
- Other features declare a `401 UNAUTHENTICATED` response in their own contracts using this shape and scope all data by the authenticated user id.
- Client renewal behavior (informative, defined in the plan): on `401 UNAUTHENTICATED` from a protected call (a request sent with the Bearer header) the client calls `refreshSession` once, retries the original call once with the new access token, and if the refresh fails clears its session and returns to `/auth`.

## 8. Reset Link (non-HTTP interface)

The mailer port receives the recipient email and this URL: `<FRONTEND_ORIGIN>/reset-password?token=<rawToken>`, where `rawToken` is the 256-bit base64url raw value (URL-encoded for safety). The frontend reads `token` from the query string and sends it verbatim in `resetPassword`. Only the hash of the token is ever stored.

| :-- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | The FDS says name has "at least 2 characters" but does not say whether whitespace counts.                                                                                                              | Name is trimmed before validation and storage, so `"  "` is `Name is required.` and `" A "` is `Name must be at least 2 characters.`. This matches the FDS trimming already used for Google names. Password is never trimmed.                                                                                      |
| A2  | The FDS has no message row for `token`.                                                                                                                                                                | `fieldErrors.token` MUST exist when the token is missing or empty; its text is implementation-defined and never displayed (the reset page makes no call without a token; Google tokens come from Google's SDK). Tests assert the key and a non-empty string, not the text.                                         |
| A3  | The FDS lists no 500 code.                                                                                                                                                                             | `INTERNAL_ERROR` with a fixed non-leaking message (section 5), per the rule in `rules/conventions.md` that unexpected failures return 500. The frontend uses generic copy for it.                                                                                                                                  |
| A4  | Rotating refresh tokens with no reuse window (FDS section 3): two browser tabs restoring at the same instant share one cookie, and the loser of the race gets `401` and treats that tab as signed out. | Left as specified by the FDS. Single-flight refresh inside one tab prevents self-inflicted races. Cross-tab races are an accepted v1 limitation.                                                                                                                                                                   |
| A5  | The FDS lowercases `email` but does not say it is trimmed.                                                                                                                                             | The server trims `email` (and then lowercases it) before validation, lookup and storage, alongside the name trimming in A1; the frontend trims the same value before validation and submit. A whitespace-only email is `Email is required.`. Password and tokens are never trimmed. Recorded as plan decision D-8. |
