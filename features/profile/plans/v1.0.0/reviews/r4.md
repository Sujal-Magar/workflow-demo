- **Conflicts with:**

  - `plan.md` Decision Log D-18 (line 37), which explicitly states the toast is `"All profile data has been cleared."` and that no `contract.md` change was needed because it already matched.
- **Severity condition:**
  - **(a) Spec violation**: `FE-07`, `behavior.md` §5, and `contract.md` §5.5 unanimously require the UI to show `"All profile data has been cleared."`. If the UI/E2E Test agent (Phase 8) follows `T-UI-07` literally — as the Testing section's exact-quote convention is designed for it to do — it writes a test asserting a different, superseded string. Built correctly per `FE-07`/`behavior.md`, that test fails against correct production code.
  - **(d) Gate cannot pass as planned**: Phase 8's exit criterion ("all tests pass") cannot be met without either silently diverging from `T-UI-07`'s literal text or failing a correctly-implemented feature. This is exactly the defect-vs-bad-test ambiguity Diagnosis Mode exists to resolve — avoidable here, at a fraction of the cost.

`fds.md` §5's Description column reads "Exports all user financial records and preferences" and "Clears all financial data while retaining account identity." Worth closing out alongside B-1 so `fds.md` stops contradicting itself.

### A-2 — `visuals/profile-page.png` shows `INR (₹)` as Preferred Currency; `fds.md`'s enum has no `INR`

The mockup's Preferences card displays `Preferred Currency: INR (₹)`, but `fds.md` §2's `preferredCurrency` enum is `NPR | USD | EUR | GBP` (default `NPR`), which has no `INR` member. `plan.md` `FE-06` follows the FDS enum (example `NPR (₹)`) rather than the visual's literal value — the only choice consistent with the data model — but no Decision Log entry or addendum records this visual/FDS mismatch the way D-16 did for the nav-header gap. Advisory under the Severity carve-out ("values that Phase 6 UI Review checks anyway"): Phase 6 will need to explicitly confirm the UI is expected to diverge from the mockup's example currency value.

### A-3 — `plan.md`'s provenance line (line 8) doesn't narrate the Round 3 (D-18) revision

The "Sources synthesized" paragraph narrates "Revision round 1" (D-16) and "Revision round 2" (D-17) but never mentions a Round 3 revision, even though D-18 is fully present in the Decision Log and `activity-log.md` confirms a "Synthesis (revision 3)" pass applying it.
